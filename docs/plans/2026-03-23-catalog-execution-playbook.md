# Catalog Execution Playbook

> Step-by-step process for producing, packaging, and distributing each catalog.

## Per-Catalog Production Workflow

### Step 1: Run the Crawl (~45 min)

```bash
# Start Claude Code in the target directory
cd catalogs/{topic-slug}
```

```
/massive-crawl "{topic description}"
```

**Tuning decisions during the run:**
- Sub-domains: accept scout suggestions + add any obvious gaps
- Agents: 6-8 for most topics, 8 for topics with >800 expected repos
- Pruning: min-score 3, min-stars 10 for broad catalogs; min-score 5, min-stars 50 for curated catalogs
- Gap review: always do one round — scouts miss niche sub-domains

### Step 2: Map Capabilities for Top Entries (~30 min, optional)

Only for Priority 1 catalogs (topics 1-5). Generates deep capability docs for top-scored entries.

```
/map-capabilities --catalog catalog.json --output-dir capabilities/
```

Run for the top 30-50 entries (score >= 8). Skip for lower-priority catalogs until the repo gains traction.

### Step 3: Write the Catalog README (~15 min)

Each catalog gets its own README.md with this structure:

```markdown
# {Topic}: Every Open-Source Tool on GitHub

> {N} repositories discovered, scored, and cataloged by [everything-on-earth](../../README.md).
> Last crawled: {YYYY-MM-DD}

## Highlights

- **{N} total repos** across {M} sub-domains
- **Top rated:** {top 3 repos with 1-line descriptions}
- **Fastest growing:** {repos with most recent activity}

## Browse

- [Interactive Explorer](explorer.html) — search, filter, sort in your browser
- [Full Catalog](catalog.json) — machine-readable, load into any LLM context
- [Summary Report](RESULTS.md) — stats and domain breakdown

## Sub-domains

| Domain | Repos | Avg Score |
|--------|-------|-----------|
| {domain} | {count} | {avg} |
| ... | ... | ... |

## How This Was Made

This catalog was generated by [everything-on-earth](../../README.md), a Claude Code plugin
that sends a swarm of AI agents to discover every repo in a domain. The pipeline is deterministic —
no LLM touches the merge, dedup, or scoring aggregation.

**Want to catalog your own topic?** Install the plugin and run `/massive-crawl "your topic"`.
```

### Step 4: Commit and Push

```bash
git add catalogs/{topic-slug}/
git commit -m "catalog: add {topic} ({N} repos)"
git push
```

### Step 5: Distribute

Execute within 48 hours of shipping. One channel per day to avoid looking spammy.

**Day 1 — Reddit:**
- Post to the primary subreddit for this topic
- Title format: "I cataloged every open-source {topic} tool on GitHub — {N} repos with scores, metadata, and an interactive explorer"
- Include: screenshot of explorer.html, top 5 repos, link to repo
- Cross-post to r/programming if relevant

**Day 2 — Hacker News:**
- Title: "Show HN: {N} open-source {topic} tools, auto-discovered and scored"
- Post link directly to the catalog README on GitHub
- Be in comments to answer questions within first 2 hours

**Day 3 — Twitter/X:**
- Thread format: hook → stats → top 5 repos → explorer screenshot → link
- Tag relevant accounts (framework authors, community leaders)
- Use topic-specific hashtags

**Day 4 — Dev.to / Hashnode:**
- Article: "The Complete Guide to Open-Source {Topic} Tools in 2026"
- Embed top repos with descriptions and scores
- Link to explorer.html and the GitHub repo
- Mention everything-on-earth as the tool that produced it

## Quality Checklist (per catalog)

Before shipping, verify:

- [ ] catalog.json is valid JSON with >100 entries
- [ ] explorer.html loads and search/filter works
- [ ] RESULTS.md has accurate stats
- [ ] No duplicate repos (dedup ran cleanly)
- [ ] Catalog README has highlights, sub-domain table, and "how this was made" section
- [ ] Top 10 repos are actually relevant (spot-check)
- [ ] Score distribution looks reasonable (not all 10s or all 3s)
- [ ] No broken repo URLs in top 20 entries (spot-check)
- [ ] "Last crawled" date is accurate

## Re-run Strategy

Catalogs in EXTREME/VERY HIGH churn domains get stale fast. Plan:

- **Monthly:** Topics 1, 3, 4 (AI agents, local AI, MCP) — landscape changes weekly
- **Quarterly:** Topics 2, 5, 6, 7, 8 (self-hosted, RAG, DevOps, cybersecurity, scraping)
- **Biannually:** Everything else

Each re-run:
1. Run /massive-crawl with same config
2. Diff against previous catalog.json (new repos, removed repos, score changes)
3. Update catalog README with "Updated: {date}, +{N} new repos"
4. Post update to original Reddit/HN threads if they're still active
