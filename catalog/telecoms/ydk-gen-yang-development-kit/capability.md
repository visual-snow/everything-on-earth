YDK-Gen is a code-generation toolkit that consumes YANG model bundle profiles and produces strongly-typed SDKs for Python, Go, and C++. It integrates model analysis, runtime validation, and language bindings into a single generation pipeline, enabling developers to interact with network devices through a type-safe, model-driven API. The tool ships with built-in service providers for the major network management protocols used in production environments.

## Protocol Support

- NETCONF — full read/write/subscribe operations via the NETCONF service provider
- RESTCONF — REST-based configuration access via the RESTCONF service provider
- OpenDaylight — northbound API integration via the ODL service provider
- gNMI — streaming telemetry and configuration via an optional service package requiring separate gRPC and protobuf dependencies

## Code Generation Modes

- Core SDK generation for each target language independently
- Bundle generation from a profile that specifies YANG model sources by directory, file, or Git repository
- Adhoc bundle generation for a named set of YANG files without a formal profile
- Service package generation for optional protocol extensions such as gNMI
- Documentation and test scaffold generation from the same profile input

## Testing and Validation

- Per-language unit test runners for Python, Go, and C++ with pass/fail reporting
- YANG model syntax and dependency validation surfaced during bundle generation
- Test infrastructure includes a NETCONF server adapter, a REST stub server, and a TCP proxy for transport-level testing
- Code coverage and quality metrics tracked via external badge integrations

## Configuration Surface

- Environment variables control repository root, virtual environment location, Go installation paths, C/C++ header and library directories, and gRPC runtime library paths
- Bundle profile JSON specifies name, version, core version, and one or more YANG model sources
- Language selection and output directory are specified at generation time via command-line flags

## Constraints

- Python 3.5 or later with a shared library build is required; Python 2 is not supported
- Running the full NETCONF unit test suite requires a Cisco ConfD license, which is not included in the repository
- The gNMI service package must be installed separately and depends on specific pinned versions of gRPC and protobuf
- Bundles generated with version 0.8.6 are not backward compatible with bundles generated by version 0.7.2 or earlier
- Installing the C/C++ core components requires root or sudo access
- Windows native execution is not supported; Windows users must run the tool inside a Linux subsystem environment
