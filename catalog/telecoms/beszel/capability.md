Beszel is a lightweight server monitoring platform that collects and displays historical metrics from remote hosts through a central web dashboard. It pairs a hub application backed by a SQLite database with per-host agent daemons that stream metrics over SSH. The platform supports multi-user access, configurable alerts, and automatic backups.

## Metrics Collection

- CPU usage for the host and for individual containers
- Memory usage including swap and ZFS ARC cache, for host and containers
- Disk usage across multiple partitions and devices
- Disk I/O across multiple partitions and devices
- Network usage for the host and containers
- Load average for the host
- Temperature readings from host sensors
- GPU usage and power draw for Nvidia, AMD, and Intel graphics processors
- Battery charge level for the host
- S.M.A.R.T. disk health including wear indicators and RAID array status
- Status and resource usage for all running containers managed by Docker or Podman
- Systemd service status

## Configuration

- Hub-to-agent communication is authenticated with an SSH ED25519 key pair generated by the hub
- Additional filesystems can be monitored by mounting their paths into the agent
- Multi-user support allows users to manage their own systems; administrators can share systems across users
- Authentication supports OAuth and OIDC providers; password authentication can be disabled
- Backups can be directed to local disk or S3-compatible object storage

## Deployment Modes

- Hub and agent deployed on separate hosts
- Hub and agent co-located on the same system via a host-gateway network bridge
- Agent installed as a systemd service without container runtime
- Nvidia GPU monitoring enabled via a dedicated agent variant requiring the Nvidia container runtime

## Constraints

- The hub must generate the SSH key pair before the agent is deployed; the agent will not start without a valid public key supplied at launch
- The agent must run with host networking to collect host-level network and hardware metrics
- Container metrics require read-only access to the Docker socket; without it, per-container statistics are unavailable
- Hub and agent communicate exclusively over SSH; the web UI port is not used for metric data transfer
- Disk I/O statistics may require an explicit filesystem device override when automatic detection is insufficient in containerized environments
