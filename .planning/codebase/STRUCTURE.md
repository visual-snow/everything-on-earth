## Directory Purposes

**`workflows/`:**
- Purpose: Source-of-truth for agent behavior; never contains platform code.
- Contains: `contract.md` (phases, invariants), `manifest.json` (workflow metadata), `runtime.json` (stage/role/artifact boundaries), `schemas/` (JSON schemas), `prompts/` (prompt templates), `examples/` (example data).
- Key files: `workflows/massive-crawl/contract.md`, `workflows/map-capabilities/contract.md`, `workflows/capability-router/contract.md`.

**`adapters/claude/`:**
- Purpose: Binds workflow contracts to Claude Code; skills trigger automatically when Claude detects the matching intent.
- Key files:
  - `adapters/claude/skills/massive-crawl/SKILL.md` — crawler orchestration skill
  - `adapters/claude/skills/map-capabilities/SKILL.md` — capability mapper skill
  - `adapters/claude/skills/capability-router/SKILL.md` — query router (generated by `build_capability_graph.py`)
  - `adapters/claude/skills/domain-telecoms/SKILL.md` — telecoms deep-navigation skill (generated)
  - `adapters/claude/models.json` — model tier per role (haiku for scouts/enrichers/classifier, sonnet for discoverers/researcher/writer/judge)
  - `adapters/claude/hooks/` — lifecycle hook scripts

**`pipeline/`:**
- Purpose: All deterministic data transformations. No LLM calls.
- Key files:
  - `pipeline/pipeline.py` — stages: `dedup`, `score`, `finalize`, `site`
  - `pipeline/build_capability_graph.py` — capability graph builder + Claude skill generator
  - `pipeline/discover_candidates.py` — Firecrawl search + GitHub API candidate collector (used by discoverer agents)
  - `pipeline/generate_capabilities.py` — wave progress tracker for map-capabilities workflow
  - `pipeline/sync_catalog_layout.py` — syncs folder-per-entry layout; imports telecoms from external `task-designer` repo
  - `pipeline/utils.py` — `slugify()`, `load_catalog()`

**`catalog/`:**
- Purpose: Persistent artifact store; 11 domains as of 2026-03-27: `biology`, `cybersecurity`, `education`, `fintech`, `gaming`, `geopolitics`, `healthcare`, `legal`, `sustainability`, `telecoms`, `trading`.
- Structure within each domain:
  - `catalog.json` — flat array of all entries, sorted by `quality_score` desc
  - `<slug>/entry.json` — full entry object including schema extensions for that domain
  - `<slug>/factsheet.json` — structured capability evidence (currently only in `telecoms/`)
  - `<slug>/capability.md` — prose capability description (currently only in `telecoms/`)
  - `detail/<slug>.html` — generated detail pages; not hand-edited

**`capability-graph/`:**
- Purpose: Pre-compiled read-only knowledge base consumed by AI skills at query time.
- Key files:
  - `capability-graph/ontology/capability-registry.json` — all capabilities with IDs, aliases, `implemented_by`, `related_capabilities`, and evidence paths
  - `capability-graph/ontology/aliases.csv` — raw-string aliases to canonical IDs
  - `capability-graph/graph/graph.json` — global graph (all domains)
  - `capability-graph/graph/domains/telecoms.json` — telecoms domain graph slice
  - `capability-graph/exports/csv/domain-routing.csv` — routing hints: domain, keyword, source, weight
  - `capability-graph/exports/csv/telecoms-capability-map.csv` — flat repo/capability mapping

**`discovery/`:**
- Purpose: Raw per-sub-domain discovery JSON outputs from discoverer agents before pipeline processing.
- Files: named by sub-domain (e.g., `ai-security.json`, `forensics-ir.json`); serve as input to `raw-discovery.json` concatenation.

**`tests/`:**
- Purpose: pytest suite covering pipeline determinism, catalog schema contracts, capability graph correctness.
- Key files: `test_pipeline.py`, `test_capability_graph.py`, `test_repo_contracts.py`, `test_sync_catalog_layout.py`, per-domain tests (e.g., `test_biology_catalog.py`).

**`training-stack/`:**
- Purpose: Docker Compose stack for training/evaluation environments; independent sub-project with its own `docker-compose.yml`.

## Key File Locations

**Entry Points:**
- `pipeline/pipeline.py` — run stages with `--stage dedup,score,finalize` or `--stage site`
- `pipeline/build_capability_graph.py` — rebuild capability graph with `--adapter claude`
- `adapters/claude/skills/*/SKILL.md` — Claude skill definitions loaded as agent context
- `index.html` — root of the generated static site

**Configuration:**
- `.claude/settings.local.json` — Claude hook configuration (hook scripts and triggers)
- `adapters/claude/models.json` — model tier per workflow role
- `workflows/*/runtime.json` — stage/role/artifact boundaries for each workflow
- `pipeline/requirements.txt` — Python dependencies (Jinja2)
- `package.json` — npm metadata and `npm test` script

**Core Logic:**
- `pipeline/pipeline.py` — `run_dedup()`, `run_score()`, `run_finalize()`, `run_site()`, `compute_edges()`, `normalize_entry()`
- `pipeline/build_capability_graph.py` — `extract_capabilities()`, `build_domain_routing()`, `build_global_graph()`, `generate_claude_skills()`
- `pipeline/utils.py` — `slugify()`, `load_catalog()`

**Templates:**
- `pipeline/templates/base.html` — CSS design tokens, sidebar layout, shared nav
- `pipeline/templates/explorer.html` — standalone unified explorer (client-side JS filtering, no base.html)
- `pipeline/templates/detail.html` — extends `base.html`; renders entry metadata + capability.md content + nearby repos

**Contracts:**
- `workflows/massive-crawl/contract.md` — 4-phase discovery and catalog production process
- `workflows/map-capabilities/contract.md` — researcher/writer/judge capability documentation process
- `workflows/capability-router/contract.md` — domain routing with classifier and fallback logic

## Naming Conventions

**Files:**
- Python scripts: `snake_case.py`
- Catalog artifacts: `entry.json`, `factsheet.json`, `capability.md` (fixed names)
- Discovery files: `<sub-domain>.json` with hyphens (e.g., `container-cloud-security.json`)
- Templates: `<name>.html` or `<name>.md.jinja`
- Skill files: `SKILL.md` (always uppercase)
- Workflow files: `contract.md`, `manifest.json`, `runtime.json` (always lowercase)

**Directories:**
- Catalog entries: `<github-owner>-<repo-name>` (slug format, hyphens)
- Domains: lowercase, hyphens (e.g., `cybersecurity`, `gaming`, `telecoms`)
- Adapter skills: match workflow name (e.g., `massive-crawl`, `map-capabilities`)
- Generated domain skills: `domain-<name>` prefix (e.g., `domain-telecoms`)

## Where to Add New Code

**New catalog domain:**
- Create `catalog/<domain>/` with a `catalog.json`
- Run `python pipeline/pipeline.py --stage site` to generate detail pages
- Add per-entry directories with `entry.json` via `sync_catalog_layout.py` or manually

**New pipeline stage:**
- Add a function in `pipeline/pipeline.py`
- Add a stage handler in `main()` under the existing `if stage ==` chain
- Add tests in `tests/test_pipeline.py`

**New workflow:**
- Create `workflows/<name>/contract.md`, `manifest.json`, `runtime.json`
- Create `adapters/claude/skills/<name>/SKILL.md` that references, not duplicates, the contract
- Optionally create `adapters/codex/skills/<name>/` for Codex support

**New capability-graph domain (beyond telecoms pilot):**
- Add `provides[]` arrays to per-entry `entry.json` files in `catalog/<domain>/`
- Run `python pipeline/build_capability_graph.py --pilot-domain <domain> --adapter claude`

**New Jinja2 template:**
- Add to `pipeline/templates/`
- Extend `base.html` with `{% extends "base.html" %}` and `{% block content %}` unless the page is fully standalone (like `explorer.html`)

## Special Directories

**`.planning/codebase/`:**
- Purpose: Analysis documents consumed by GSD planning tools.
- Generated: By GSD map-codebase agent.
- Committed: No (should remain in .gitignore or local only).

**`.firecrawl/`:**
- Purpose: Cached Firecrawl search result payloads by sub-domain.
- Generated: By discoverer agents during massive-crawl workflow.
- Committed: Yes (acts as a reproducibility cache).

**`.superpowers/brainstorm/`:**
- Purpose: Temporary brainstorm session artifacts from supercharge skill.
- Generated: Automatically during brainstorm sessions.
- Committed: No.

**`capability-graph/`:**
- Purpose: Build artifact; fully regenerated by `build_capability_graph.py`.
- Generated: Yes, from catalog data.
- Committed: Yes (used as read-only context by skills at runtime without re-derivation).
